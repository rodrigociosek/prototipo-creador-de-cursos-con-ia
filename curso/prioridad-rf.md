# Prioridad de RF

Confirmado por el usuario el 2026-07-22.

| Orden | RF | Por qué va en esta posición |
|-------|----|------------------------------|
| 1 | RF-06 | Crear una tarea es la acción más básica del producto — sin ella no hay nada que listar, completar, editar ni eliminar. Es el camino feliz principal. |
| 2 | RF-05 | Ver la lista de tareas es la comprobación inmediata de que el producto cumple su propósito; el usuario lo nota apenas abre la app. |
| 3 | RF-07 | Marcar una tarea como completada es la acción distintiva de un todo-list — el "check" es el motivo por el que existe este tipo de software. |
| 4 | RF-08 | Editar una tarea completa el ciclo básico de gestión, muy visible si faltara. |
| 5 | RF-09 | Eliminar una tarea cierra el CRUD básico de gestión de tareas. |
| 6 | RF-01 | El registro habilita que existan cuentas separadas — necesario antes de que tenga sentido "iniciar sesión". |
| 7 | RF-02 | El inicio de sesión habilita el acceso autenticado; muy visible (es la puerta de entrada a la app), pero depende conceptualmente de que exista el registro (RF-01). |
| 8 | RF-04 | El aislamiento por usuario le da sentido real a tener cuentas separadas — cierra el círculo entre la autenticación (RF-01/02) y la gestión de tareas (RF-05–09). |
| 9 | RF-03 | Cerrar sesión es necesario pero menos crítico que poder entrar; el usuario lo nota, pero no bloquea el uso básico del producto si se retrasa. |
| 10 | RF-10 | Añadir teléfono y recordatorio a una tarea es una mejora opcional (así lo dice el propio documento de funcionalidades) sobre la gestión de tareas ya cubierta. |
| 11 | RF-11 | El envío automático de SMS es la culminación de RF-10 — sin RF-10 no tiene sentido, y es una funcionalidad secundaria frente al núcleo del producto. |
| 12 | RF-12 | El feedback visual de carga y errores es soporte/robustez transversal a toda la interfaz — mejora la experiencia pero no es una funcionalidad en sí misma. |
